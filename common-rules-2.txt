COMMON RULES 2 (apply to every new page in the stages below)
1. Also read common-rules.txt. If this file and common-rules.txt disagree, THIS file wins.
2. Tools with NO file upload (calculators, generators, text tools): use a 2-step flow "1. Enter ..." then "2. See or copy ...". Privacy line: "Nothing is uploaded or saved. Everything works on your device."
3. Tools WITH file upload: keep the 3-step flow (Upload, Choose, Download) and the line "Your file never leaves your phone or computer."
4. KEYWORDS: every page has ONE primary and several SECONDARY keywords listed in the stage prompt. The primary goes in the title tag (first), H1, meta description, URL slug, first sentence, one image alt text and one FAQ. Each secondary is used ONCE, naturally, in the subtitle, a how-to line, a FAQ or an H2. Never stuff. Use no keyword that is not listed. A keyword marked (*) is an unverified variant: use it once and no more.
5. Append every new page to keyword-map.md (URL, primary, secondary list).
6. CONTENT PER PAGE: H1, subtitle (max 15 words), the tool, privacy line, 3-step how-to, 3 UNIQUE FAQs (different wording and situations, never just a swapped number), 4 "More tools" links. About 120 to 200 words outside the tool. Title tag under 60 characters: "Primary Keyword - Free Online | FileShrink". Meta description 140 to 155 characters with "free" and "no signup" (add "no watermark" only if the tool creates a file). Canonical URL, Open Graph tags, JSON-LD (WebApplication, FAQPage, BreadcrumbList) and reserved ad slots, never inside or touching the tool.
7. NUMBERS: keep exact values, round only for display, never show NaN, Infinity or scientific notation. Empty, zero-where-invalid, negative and letter inputs show plain friendly messages, never a wrong answer. Use inputmode="decimal" or "numeric". Show the formula in one short plain sentence under each result. Keep all constants in ONE labeled config block at the top of the script.
8. Do not invent facts (rates, laws, platform sizes, official rules). Any platform size or limit in a config block must carry the comment "verify against the platform's current guidance", and must be listed in your final report.
9. Reuse shared code. Do not duplicate code. Do not change working tool code unless needed. Never save user content in localStorage; only settings, inside try/catch, and the page must work if storage is blocked.
10. SITE UPDATES for every new page: add it to the homepage under the best-fitting section (create a section if none fits), the header menu groups (accordion on mobile), sitemap.xml, the homepage search filter, and the "More tools" links of related pages.
11. TESTING: run or trace every listed test and show a table: Test | Expected | Actual | Pass/Fail. Check 320px, 375px and 768px, and no console errors. If you cannot run something, say so plainly.
12. At the end, list every file changed, everything uncertain, and stop.
